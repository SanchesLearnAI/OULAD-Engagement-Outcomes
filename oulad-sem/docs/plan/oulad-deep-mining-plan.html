01 证据底座

先分清“已核验”与“听起来合理”

两轮 deep-research 在 2026-11-03 做了断点复跑：第一轮 18 个源、89 条候选 claim，最终 9 条确认、8 条被驳回、8 条仍未核验；第二轮 25 个源、121 条 claim，23 条确认、2 条驳回、0 条未核验。下面只把核验过的结论当硬约束；被驳回的数字单独列出，不再进入方案。

结论证据状态对方案的影响
studentVle.date 是相对 presentation 开课日的整数天，范围 −25 到 269；22 个 presentation 都有负值，共 688,988 行（6.47%）。 已核验 3–0 W1 必须按 0 ≤ date ≤ 27 在 module × presentation 内切；开课前点击必须显式选择排除/裁剪/单列。
观测单位是选课记录，不是唯一的人；行级随机划分会让 852 名学生同时进入训练与测试，影响 15.7% 的测试记录。 已核验 3–0 必须 GroupShuffleSplit / GroupKFold；把“学生不重叠”写成 S05 的硬断言。
时间外推会明显掉性能：2013 训练→2014 测试 AUC 0.7470（95% CI 0.7393–0.7549）；leave-one-module-out 0.6426–0.7881，中位数 0.6990。 已核验 3–0 随机划分的 CV 不能当部署预期；主表必须同时给 group CV、2013→2014、LOMO 三套数字。

LEAP 的周级 cutoff：AUC 从第 1 周 0.7151 升到第 2 周 0.7404、第 3 周 0.7851、第 4 周 0.8055、第 8 周 0.8602；第 2→3 周增幅最大（+0.0447）。 已核验 3–0 · 预印本 这是 W1→W8 分阶段设计的直接模板；4→8 周的增量约 +0.055 AUC，可作为 S09 的预期量级，但目标定义不同。
时间泄漏会把早期性能抬高约 0.25 AUC：同一流程 t=7 严格协议 0.7151，含未来信息 0.9669（GBDT 0.7147→0.9704）。 已核验 3–0 · 预印本 S04 的泄漏断言不是形式；任何“前四周 AUC > 0.9”的结果，先当成泄漏嫌疑，查特征日期与来源。
常被引用的全课程 LSTM（93.46% precision、75.79% recall、95.23% accuracy）使用 1–38 周数据，未报告 AUC/F1/PR-AUC，也未说明划分方式，不能当前四周基线。 已核验 2–0 文献综述里可以引用，但必须标注“full-course retrospective”；不要拿它和 day-28 模型比。
Withdrawn 的官方语义是“退课”，但本轮关于 date_unregistration 与退课后点击流截断的捆绑断言被 0–3 驳回；不能假设退课后的点击一定被截断。 需原始 CSV 审计 S02 必须先审计退课者的点击分布与 date_unregistration 关系，再决定 at-risk 队列；不要照搬“按日期剔除”的写法。
点击不是 time-on-task：点击间隔无法区分精读、离开与多任务；15 种估计策略使同一模型 R² 平均相差 0.15（0.07–0.23），且无现场观测金标准。 已核验 3–0 不构造 time-on-task 特征；“点击/活跃天”只能作弱代理，并在限制里写明估计假设。
trace 与 self-report 不是同一构念：反应风格解释问卷方差最高 43%，对 trace 最高 4%；process 型 trace 在控制 mastery 后可转负或消失。 已核验 3–0 不要把点击直接叫“投入”；用多种操作化（总量、构成、规律性、时点）并做规格曲线，避免单一指标的结论被换定义推翻。
“相似用量、不同结果”更支持时间轨迹与策略调整：相对投入上升的学生通过率更高；高表现者按单元调整策略，低表现者无显著调整；频率聚合会丢事件顺序。 已核验 3–0 · 中等 W2 的 Δ、斜率、活动构成迁移应作为核心特征；总量只作 baseline，不作主解释。
教学情境是一阶混杂：课程特异模型与合并模型在预测力和显著变量上都不同；忽略教学条件会把 LMS 特征效应高估或低估（方向不定）。 已核验 3–0 匹配必须包含课程/教学设计层协变量；主分析按 module × presentation 分层，合并模型加固定效应。
从观察到因果有边界：按结果分组再观察行为，可能把期望结果“投射”到行为上；原作者明确否认策略使用足以解释成绩差异。 已核验 3–0 匹配与轨迹分析只写关联/预测；加 E-value，不写“导致”。
聚类稳定性报告在实务中常缺失：被评述的 EM 研究只报 BIC 与 MANOVA/ANOVA+Bonferroni，无 bootstrap、ARI 或 silhouette。 已核验 3–0 · 中等 本项目必须报 bootstrap ARI/Jaccard + consensus；但“ARI 阈值多少算稳定”在本轮未核验，按方法学共识执行并标注。
PSM/CEM 的平衡诊断、共同支撑、caliper、PR-AUC 与校准的报告规范，本轮没有已核验 claim 覆盖。 覆盖缺口 继续按 Rosenbaum & Rubin、Austin、Stuart、Iacus/King/Porro、Saito & Rehmsmeier、Van Calster 的方法学共识执行，但写成“方法共识”，不冒充本轮证据。

这份证据底座改变的不是“要不要做匹配/聚类/分类”，而是每个分析步骤的默认设置：窗口按相对日切、划分按学生分组、退课先审计、成绩不进严格特征、聚类必须报稳定性、任何异常高的性能先查泄漏。下面按三个层次展开：预处理、预处理后的分析、进一步挖掘。

02 数据预处理

先把数据变成“每个 cutoff 都能安全复现”的分析表

2.1 建表与粒度

主键统一为 (code_module, code_presentation, id_student)。先把 studentInfo 与 studentRegistration 合成选课主表，再左连接课程长度、VLE 聚合、评估聚合。所有聚合都必须带窗口参数，不能先算全期再切。

表粒度在方案中的用途
studentInfo选课记录标签 final_result；静态背景变量只作分层/调整，不进主叙事。
studentRegistration选课记录date_registration、date_unregistration；后者只用于队列定义，不能当特征。
studentVle学生 × 日期 × 站点点击流主表；按日、按活动类型、按窗口聚合。没有会话级时间戳。
vle站点 × presentationactivity_type 映射；week_from/week_to 用于判断资源何时可用。
assessments评估 × presentation截止日、权重、类型；用来定义“第一次大作业”和截止日前行为。
studentAssessment学生 × 评估严格模式只用 date_submitted；score 与 is_banked 单独审计。
courses模块 × presentation课程长度；用于检查窗口是否落在课程范围内。

2.2 结果变量与队列

原 proposal 的二分类是 Pass/Distinction vs Fail，并把 Withdrawn 单独描述。这个方向可以保留，但必须把“三种标签方案”显式化，否则 base rate 和模型指标会不可比。

方案正类 / 负类适合回答代价
T1 主分析 Pass/Distinction = 1；Fail = 0；Withdrawn 排除 与 proposal 对齐：在完成课程的人里，早期行为能否区分通过与否 样本损失；结论不能外推到退课人群
T2 风险视角 Pass/Distinction = 1；Fail + Withdrawn = 0 早期预警：谁需要被关注 把“放弃”和“失败”混成一种机制，解释力下降
T3 稳健性 Pass/Distinction、Fail、Withdrawn 三分类 保留三种结果，检查 T1 结论是否依赖排除规则 多分类指标更复杂；小类不平衡
T4 进阶层 cause-specific hazard：Pass/Fail/Withdrawn 退课时间本身作为结果 需要生存分析；课程项目里可作扩展

At-risk 队列（先审计，再定义）：不要直接按 date_unregistration ≤ c 剔除。本轮把“Withdrawn 编码 + 退课后点击流截断”捆在一起的断言被 0–3 驳回，所以 S02 必须先审计退课者在退课前后是否仍有点击、点击分布是否在退课后停止。只有审计支持“退课后没有新点击/结果已定”时，才剔除；否则保留全队列，把退课状态交给 T3 / 竞争风险。报告两套数字：全队列和审计后的 at-risk 队列，两套 base rate 不能混着解释。

2.3 时间轴与窗口

date 是相对开课日的天数，day 0 = presentation 开始。W1 取 0 ≤ date ≤ 27。W2 取 28 ≤ date ≤ min(55, first_tma − 1)，其中 first_tma 是该 presentation 中权重 > 0 的第一次 TMA/CMA 截止日；如果该日期早于第 4 周，就退回固定的 28–55 并注明。

开课前点击的三种处理必须选一种并写清楚：严格排除（主分析）、裁剪到 day 0、或作为单独的 pre_start_clicks 特征（敏感性）。抽查的 4 个模块中，约 7.58% 的 studentVle 行日期为负，最早到 −25 天；这不是可以忽略的边角。

Cutoff 扫描：c ∈ {14, 21, 28, 35, 42, 49, 56, first_tma}。每个 c 只允许使用 date < c 的点击与提交事件。不要用“全期聚合后再截断”，那等于把未来信息压缩进特征。

2.5 特征工程

不要只做“总点击”。OULAD 只有“日期 + 当天点击总数”，没有会话级时间戳，所以 time-on-task 只能估，不能测；把“点击 / 活跃天”当成弱代理可以，但要在限制里写清楚。特征按族建，每族都能独立开关，方便消融。

族典型特征窗口它想捕捉什么
总量clicks_total、log1p(clicks)、每周点击数W1 / W2 / Δ参与强度；长尾，必须 log
活动构成各 activity_type 点击占比、熵、GiniW1 / W2学习策略的资源组合，而非单纯“多不多”
广度活跃天数、不同站点数、不同活动类型数W1 / W2接触面；与总量相关但不等价
规律性日点击 CV、最长空窗、活跃周数、周末占比、连续活跃段W1 / W2“怎么分布”比“多少”更接近研究问题
时点距上次点击天数、截止日前 48h 点击、提交时间W1 / W2临期冲刺 / 拖延；不含成绩

背景module、presentation、gender、age、education、IMD、disability、prev attempts、credits静态只作分层/调整；不作主叙事，避免把人口变量当解释
不进入time-on-task 估计、任何 cutoff 后聚合、评估分数—不可得或泄漏

命名建议：w1_ / w2_ / d_ 前缀 + 族 + 统计量，例如 w1_clicks_total、w1_active_days、w1_entropy_activity、d_clicks_ratio。一个特征构造函数同时接收 cutoff，保证任何窗口都能重算。

2.6 清洗与标准化

  • 先把 studentVle 聚合到 (id_student, presentation, date, id_site)，避免重复行放大点击量。
  • 缺失的分类变量保留为 Unknown，不要用众数插补背景变量；缺失本身可能携带信息。
  • 零点击学生：留在预测队列（零点击是信息），排除出聚类（没有 profile 可聚），并报告人数。
  • 低活跃阈值做敏感性：0 / 5 / 10 / 20 次 W1 点击，看结论是否依赖阈值。
  • 点击量在 presentation 内做 1%/99% winsorize，再 log1p；聚类前在 presentation 内 z-score。
  • 类别不平衡用 class weight，不在主分析里 SMOTE；如果要用，只能在训练折内生成并单独报告。

2.7 先冻结配置，再看结果

建模前写一个 config.yaml：目标方案（T1/T2/T3）、窗口边界、是否保留开课前点击、特征族开关、划分方式、指标、随机种子。所有后续表格都从这份配置生成。这样做不是为了形式，而是为了防止“看到测试结果再换切法”。

03 预处理后的分析

先证明“相似”存在，再解释“为什么不同”

3.1 描述性审计：不要把“相似点击”当成假设

  • 样本流：32,593 条选课记录 → 排除规则 → 分析队列；每一步的人数、module 分布、base rate 都要有一行。
  • 点击分布：中位数、IQR、top 1% 占比、零点击比例；长尾是否严重到需要分箱。
  • 重叠检查：在同一 presentation 内，Pass 与 Fail 的 W1 点击分布是否重叠；如果重叠很差，“相似点击”本身就不成立。
  • 退课时间：date_unregistration 的分布；多少人在 W1 内退课、多少人在 W2 内退课。这决定了 at-risk 队列怎么建。

这一步的产出是两张图：样本流图、W1 点击分布 / 重叠图。它们决定后面的匹配是否有共同支撑。

3.2 匹配比较：把“相似”做成可检查的设计

推荐在主分析里用粗化精确匹配（CEM），而不是一上来就 PSM。CEM 的平衡是设计出来的，不依赖模型设定；对课程项目也更可解释。

  • 精确层：code_module × code_presentation。只在同一门课、同一届里比较。
  • 粗化层：W1 总点击按 presentation 内十分位分箱；活跃天数按 0, 1–3, 4–7, 8–14, 15–21, 22–28 分箱；活动类型熵按三分位分箱。
  • 平衡检查：所有匹配变量的 |SMD| < 0.1；报告共同支撑与样本损失；画 Love plot。不要用“匹配后 p 值”证明平衡。
  • 结果比较：在匹配层内比较 W2 特征（点击变化、规律性、活动构成、截止日行为），给 bootstrap 置信区间；报告 ATT 式的“关联差异”，不写“效应”。
  • 不一致层：同一匹配层里既有 Pass 又有 Fail 的，是核心样本。比较他们的 W2 轨迹，而不是只比较层均值。
  • 敏感性：PSM（logit + 卡钳）作为替代；E-value 评估未测混淆需要多强才能解释掉观察到的差异。
解释边界

W1 engagement 是“基线后”变量，可能受前期成绩、课程设计、甚至结果预期影响。用它做匹配变量，等于对基线后变量做条件化，可能引入中介或对撞偏倚。因此匹配结果只能定位为描述性 / 预测性，不能写成“相似投入导致不同结果”。

3.3 聚类：找 profile，不找“学习风格”

聚类只回答一个问题：W1 的行为向量能不能形成可重复的几组？如果能，组内结果是否分化？不要给簇起“努力型 / 摸鱼型”这种本质化名字。

  • 输入：W1 的总量（log）、广度、规律性、活动构成；在 presentation 内 z-score。若共线性严重，先 PCA 到 5–8 维并报告解释方差。
  • 选 k：k = 2…8，看 silhouette、Calinski–Harabasz、Davies–Bouldin；这些只用于辅助，不能证明簇真实存在。
  • 稳定性：bootstrap / 子采样 200–500 次，报告 ARI 分布、每个簇的 Jaccard、consensus matrix；多随机起点 + k-means++。不稳定的簇合并或放弃，并把这个决定写进报告。
  • 结果交叉表：簇 × 结果（Pass/Fail/Withdrawn），带置信区间；重点找“结果混合”的簇——那才是“相同参与度、不同结果”的候选。
  • 第二层：对 W2−W1 的变化向量再做一次聚类，看“早期 profile 相同、后期轨迹不同”的组合。
  • 敏感性：Ward 层次聚类、HDBSCAN、不同特征子集；如果结论只在某一种算法下成立，就把它写成“探索性”。

3.4 分类：模型阶梯，而不是一个随机森林

用“阶梯”回答“行为结构是否带来增量信息”，而不是只报一个最好看的模型。每一级只加一族特征，比较同一划分、同一指标。

模型特征回答的问题
M0 engagement-only logistic总点击 + 活跃天数“参与量”本身能做到什么程度
M1M0 + 广度 + 规律性“怎么分布”是否带来增量
M2M1 + 时点 / 截止日行为“何时投入”是否带来增量
M3M2 + 评估提交时间（不含分数）评估节奏的增量
M4M3 + 评估分数上界对照，不是主结果
M5M3 + 随机森林 / HistGradientBoosting非线性与交互是否重要
  • 划分：按 id_student 分组 60/20/20；5 折 GroupKFold；forward-temporal（2013 训练 → 2014 测试）；leave-one-module-out。至少报主划分 + 一种外推。
  • 指标：PR-AUC 为主（少数类），ROC-AUC 用于和文献对照；recall at precision 0.7/0.8；选定阈值下的 F1；Brier、校准斜率/截距、可靠性图；bootstrap 1000 次 CI。
  • 阈值：在验证集上按误分类成本选，冻结后再看测试集。不要用测试集挑阈值。
  • 比较：配对 bootstrap 或 DeLong 检验；多模型比较时说明多重比较处理。
  • 解释：系数 + CI、permutation importance、关键特征的 PDP；相关特征之间不要做“谁更重要”的绝对排序。
  • 异质性：按 module / presentation 分别报性能；如果某模块明显更差，这本身是结果。

3.5 “先验 → 后验”：两条路线，别混着叫

把 W1 叫“先验”、W2 叫“后验”是一个有用的工程隐喻，但它不是自动成立的贝叶斯模型。先选一条路线，再决定要不要形式化。

路线做法解释风险
A. 时间切片 在每个 cutoff 单独训练 M0–M3，比较 PR-AUC / recall 随 c 的变化 “多看到 4 周，预警能力提升多少” 不是贝叶斯；不同 c 的队列不同，需固定队列对照
B1. Stacking 用 cross-fitted 的 W1 预测概率作为 W2 模型的一个特征 “W1 的判断 + W2 的新证据” W1 概率必须在训练折外生成，否则过拟合
B2. Offset 把 logit(p_W1) 作为 offset，拟合 W2 特征 “在 W1 判断的基础上更新” offset 的系数固定为 1；需检查校准
B3. 正式贝叶斯 给 log-odds 设先验，用 W2 行为构造似然，输出后验 真正意义上的先验 / 后验 先验与似然假设都要写清楚；课程项目成本高

建议：主分析用 A，扩展用 B1 或 B2。B3 只在你能写清楚先验分布、似然和校准检查时再用。无论哪条，都要报告“增量”而不是只报最终性能：ΔPR-AUC、Δrecall@precision、校准变化，并给 CI。

量级参考：LEAP 的 OULAD 周级曲线为 week1 0.7151 → week4 0.8055 → week8 0.8602（目标 Pass/Distinction vs Fail/Withdrawn，预印本）。它对应约 +0.055 AUC 的 4→8 周增量；你的目标与特征不同，只能把这个数当 sanity check。若你的增量是 +0.30，先查泄漏或队列变化。

“第一次大作业”作为事件对齐点时，注意 assessments.date 是截止日，不是评分完成日；studentAssessment.date_submitted 是提交日。两者都相对开课日。不要把“提交得早”直接解释成“学得好”，它可能只是策略差异。

3.6 竞争风险：退课不是一个可以折叠的标签

如果只用 T1（排除 Withdrawn），你回答的是“坚持下来的人里谁通过”；如果只用 T2（并入 Fail），你把“主动退出”和“考试失败”当成同一种机制。更合适的是把三者放在一个时间框架里：

前提：先用 S02 审计确认退课者的点击流是否在 date_unregistration 后停止。本轮关于“退课后点击必然截断”的捆绑断言被 0–3 驳回；如果退课后仍有点击，Withdrawn 更应作为时变状态/竞争风险，而不是静态标签。

  • 三分类：在每个 cutoff 做 multinomial logistic，报告每类的 precision/recall 与混淆矩阵。
  • Cause-specific hazard：以周为时间单位，把 W1/W2 的周度点击作为时变协变量，分别建模 Pass、Fail、Withdrawn 的瞬时风险。
  • Fine–Gray：如果关心“累积退课概率”，用 subdistribution hazard；如果关心“机制”，用 cause-specific。
  • 报告：累积发生率曲线、每类的关键协变量、以及排除/并入 Withdrawn 时结论如何变化。

这一步会让你的报告从“二分类作业”变成“对三种结果机制的描述”，也更贴合 proposal 里“withdrawal is a different outcome”的原话。

04 进一步挖掘

从“谁通过”走到“什么时候开始分岔”

4.1 轨迹分化：找到分岔周

把每个学生对齐到“第 1 周、第 2 周……”，构造周度点击向量（绝对量与占自身总量的比例两版）。先做轨迹聚类（k-means on aligned vectors 或 functional PCA），再对匹配层内结果不一致的对子做差异曲线：从哪一周开始，Pass 与 Fail 的轨迹稳定分开？

  • 差异曲线 + bootstrap 带：每周的组间差异及 CI，标出第一个持续显著的周。
  • 变化点检测：对单个学生的周度序列做简单的 change-point，汇总“分化周”的分布。
  • 案例对照：从匹配层里抽 3–5 对“早期相似、结果不同”的轨迹，作为定性说明；不要用个例代替统计。

4.2 序列与转移：在日级粒度上能做什么

OULAD 没有会话时间戳，只有“某天点了某类资源多少次”。所以真正的点击序列挖掘（PrefixSpan、Markov）只能在“天 × 活动类型”这个粗粒度上做，结论要相应降级。

  • 每个学生一条“每日主导活动类型”序列；比较 Pass/Fail 的转移矩阵与常见 n-gram。
  • 顺序模式挖掘只作为探索：报告支持度、置信度，并说明日级聚合会丢掉会话内的顺序。
  • 如果结果显示“高绩效者更常出现 A→B 转移”，先检查这是不是课程设计强制的资源顺序，而不是学习策略。

4.3 异质性与公平性

  • 按 module / presentation 分层报告性能与匹配结果；模块间差异大时，不要给一个合并的“平均效应”。
  • 按 gender、age band、IMD、disability、education 做子组校准与 error rate 检查；报告差异，但不做因果归因。
  • 如果某组的 recall 明显低，说明预警系统对该组更不敏感；这是部署前必须写出来的限制。

4.4 规格曲线与负对照

这类观察性分析最危险的不是“算错”，而是“换一个合理选择结论就翻”。用规格曲线把所有合理选择一次性摊开：

  • 变动维度：cutoff（28 vs first_tma）、开课前点击（排除/裁剪/保留）、低活跃阈值、目标方案（T1/T2/T3）、特征族（M0–M3）、匹配方法（CEM/PSM/分层）、聚类 k、模型（logistic/RF）。
  • 输出：每个规格的效应量或性能点，按大小排序画图；报告中位数、范围、以及“结论方向是否稳定”。
  • 负对照：用开课前点击预测结果（应该很弱）；随机打乱标签（应该接近 baseline）；安慰剂 cutoff（用未来窗口做同样的分析，应该没有增量）。这些是泄漏探测器。
  • 敏感性：E-value 说明未测混淆需要多强才能解释掉观察到的关联。

06 坑清单

这些错误会让前面所有工作失效

  • 行级随机划分。 28,785 个学生有 32,593 条记录，同一人跨训练/测试就是泄漏。按 id_student 分组。
  • 用全期聚合再切窗口。 先算“总点击”再取前四周，等于把未来信息压进特征。所有聚合必须带 cutoff。
  • 把评估分数当成 day-28 可得。 OULAD 没有评分完成时间；严格模式排除分数，含分数只作上界。
  • 把 Withdrawn 当缺失或直接并入 Fail。 两种失败机制被混在一起，base rate 也会变。
  • 用 accuracy 报不平衡分类。 多数类全猜对也能 70%+；用 PR-AUC、recall、F1、校准。
  • 用 silhouette 证明聚类真实。 它只说明几何分离；稳定性要靠 bootstrap ARI / Jaccard。
  • 把簇命名成本质类型。 “努力型/摸鱼型”是标签，不是机制；簇只是行为 profile。
  • 把匹配后的差异写成因果。 匹配只平衡已测协变量；W1 engagement 还是基线后变量。用“关联 / 预测”措辞。
  • 跨模块合并后直接解释。 课程设计、评估节奏、资源开放时间都不同；先分层，再考虑合并。
  • 引用未核验的 0.77 基线。 它不是本文证据；要么回原文核对，要么只写“候选研究报告了……”。
